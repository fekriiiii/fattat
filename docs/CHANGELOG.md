**Morphology prefix layer, unblocked by an open Swedish lexicon (2026-07-24, part 4)** — the founder asked whether to wire Claude to synonymer.se or svenska.se through an MCP. The research killed both and found something better.

1. **Both named sources are dead ends, and it is worth writing down so no future session re-researches it.** synonymer.se has no API and licenses its content from *Bonniers svenska ordbok*, so pulling it into a paid product is a copyright problem (checking it by hand stays fine). svenska.se has no public API either; SAOL and SO *are* in Språkbanken's Karp as `salex_saol15` / `salex_so-frys`, but those resources answer `{"detail":"Not enough permissions"}`. The best Swedish dictionary is precisely the one we cannot have programmatically.
2. **What is open, and legally clean: SALDO.** Språkbanken's morphological lexicon, 128 036 entries, **CC-BY-4.0**, free in a commercial product with attribution, reachable through the open Karp v7 API with no key. Also open: `kelly` (CEFR level + frequency), `swesaurus` (synonyms with a 0–100 degree, but only 15 010 entries and it misses HP-level words like `vederhäftig`), and **Korp's count API** for real corpus frequency per million, which is the closest thing we have to an automated HP-likeness signal.
3. **MCP was the wrong packaging and the answer was not "more sources" but one specific unblock.** The decoder runs in the student's browser and must be instant and offline, so nothing can call Göteborg per word. What v1 of the morphology decoder actually lacked was a **base-word check**: it refused to decode any word starting with `o`, because of 183 such strings in the corpus only about half are the negating prefix and the rest are opaque (`ornament`, `observera`, `område`). SALDO answers exactly that question. `scripts/build-morph-prefixes.mjs` resolves every candidate at build time and writes `src/lib/ord/prefix-lexicon.ts`. **Corpus-wide result: 60 → 170 confident decodes**, suffix layer unchanged. Chaining is the nicest part: `oanvändbar` → `o + använd + bar`.
4. **The automated check got seven wrong, and only the hand pass caught them.** Of 116 machine-accepted entries, six are semantically false despite a structurally valid split, and are rejected with reasons in the script: `oförrätt` (a förrätt is a first course), `olat` (= bad habit, unrelated to `lat`), `olustig` (= uneasy, not "not funny"), `oförskämd` (from *skam*, not `förskämd`), `otäck` (base `täck` is archaic and reads as *täcka*), `oljudande` (here `o-` means *bad*). A seventh, `omedelbar`, was **created by the new chaining** splitting `medelbar` a second time into `o + medel + bar`. Existence-checking gets ~95% of the way; the hand pass is not optional, which is the same conclusion the original corpus analysis reached. Also fixed: the gloss fallback in `MorphemeBreakdown` assumed a suffix and would have printed `‑o`.

Files: `scripts/build-morph-prefixes.mjs` (new), `src/lib/ord/prefix-lexicon.ts` (new, generated), `src/lib/ord/morphology.ts`, `src/components/ord/MorphemeBreakdown.tsx`, `analysis/ORD_morfologi.md`. Typecheck + production build green. **Not verified end-to-end** — the breakdowns need a real look in a session's ORD feedback card. *North Star: goal #1 — HP-appen ships morphology too, so the differentiator is not that we have it but where it points: they decode the headword, we decode the **answer options**, which is where students actually stall. And unlike new content this makes content we already own teach more, which is the right kind of work while the LÄS bank is the scarce resource.*

**Content QA rails, the HP-appen teardown, and the first batch on them (2026-07-24, part 3)** — the session that made scaling the LÄS bank safe, then scaled it.

1. **HP-appen teardown → `analysis/COMPETITOR_hpappen.md`.** Walked end to end on a real free account. This is a materially more serious competitor than hpspelet: 7-person team, founded 2021, ~750 monthly actives (their in-app leaderboards report participant counts, which is the most honest scale figure available anywhere in this market; their public "20 000+ studenter årligen" is cumulative signups, off by ~25×). **They already ship what we call our differentiation** — spaced repetition on ORD, quoted passage anchors in LÄS solutions, morphology on demand, immediate feedback, an AI coach. So "cognitive-science-grounded" is no longer a claim we hold alone. What survives is architecture they cannot add in a sprint: a **real scheduler** (theirs marks a word *färdiginlärd* after one correct answer, and their own community has a user with a 900-word unmanageable backlog), **error-specific feedback** (their panel is byte-identical whether you were right or wrong), **session design** (they have no session concept at all), and **self-written LÄS** (their entire 1 080-question LÄS corpus is past exams, and finite). Two verified defects worth remembering because they are our own bug classes: their AI reads **unshuffled option letters** and mislabels every distractor, and the advertised LÄS *citatmarkör* fails outright because the AI has no access to the passage. Pricing check also favours us: a full sitting costs ~900–1 200 kr there against our 399 kr, and their "mest populära" plan is a 989 kr six-month one-time purchase, which is our packaging.
2. **The content QA rails, built before the batch rather than after.** `scripts/las-checks.cjs` holds every LÄS rule in one module so the authoring path (`add-las-article.cjs`, one article) and the sweep (`lint-las-corpus.cjs`, all of them) run the *identical* check — two copies would drift within a week. New rules beyond what existed: **`passage_anchor` must appear verbatim in the body** (a fabricated citation is worse than none, and is exactly what we watched HP-appen ship), vocab highlights must resolve using **seed.ts's own matcher** so the guard predicts precisely what the seed will do, `distractor_types` keys must be real option letters, and a length ceiling. Plus `lint-ord-corpus.cjs` for the ORD side. **The lint found four live defects on its first run:** vocab highlights for `kontroversiell`, `kartlägga`, `upprätthålla` and `åkomma` use forms absent from their own bodies, so the seed wrote index -1 and **those tooltips were dead in production** — the third instance of this bug class. Two of my own checks were wrong on that first run and are now correct: anchors may join two passages with an internal ellipsis, and a quote clipped mid-sentence legitimately ends with a period the body lacks.
3. **Two content rules settled from data, not taste.** The **odd-one-out rule** and the **answer-letter balance**; both measurements and their consequences are in `docs/CHANGELOG.md` → Closed items. Short version: at least one distractor must share the correct answer's word-count class (8 curated rows fixed), and the corpus went from A 32 / B 32 / C 25 / **D 12** to **A 26 / B 28 / C 26 / D 20**, inside HP's empirical band for the first time.
4. **Six new LÄS articles, corpus 18 → 24** (ids 23–28), two complete provpass-sets, planned into the thinnest Slot C domains. Bank is now **8 kort / 16 lång = exactly the 1:2 HP ratio**, 8 complete sets, and 169 of 340 curated ORD words have an article home. **The guards paid for themselves immediately:** across six articles they caught a letter reference in an explanation, **five separate length-tells** (correct answer 1–5 characters longer than the longest distractor, in five different questions), and **four bodies under the 950-word floor**. Every one would have shipped. The length-tell is precisely the failure the distractor appendix warns is hardest to see in your own work, and it was: the machine caught all five, the author caught none.
5. **Two dogfooding fixes.** No word definitions in **övningsprov or diagnostic** — real HP offers no word aid, so giving one during a measurement inflates the very score it exists to produce, and the diagnostic also picks the study plan. `ArticleReader` takes `showVocab` (default true, daily sessions unchanged); when off the highlighted words render as plain text, since an underline you cannot tap is worse than none. And the **mobile definition sheet was unreadable**: `VocabTooltip` and `BottomNav` were both `z-50` and the nav renders later, so the nav covered the definition. Now portalled to `<body>` at `z-[60]`, with scroll-lock, Escape, and the document-level `mousedown` listener removed (it double-fired on touch and could close the sheet on the tap that opened it).

Also: the lång-length threshold now splits into a **target** (950, warned only while authoring) and a **floor** (800, HP's real span, warned always), after the founder decided the two legacy short articles stay. A warning that will never be acted on is how a team learns to ignore warnings, which matters far more at 85 articles than at 24.

Typecheck + production build green; seeded and `las:verify` reports **24/24 exact**. **Not verified end-to-end:** the mobile tooltip needs a real look on a phone. *North Star: goal #1 — the teardown is the uncomfortable half (a competitor with 7 people already says "spaced repetition" in their UI), and the rails are the answer to it. We cannot out-claim them; we can out-execute them, and the evidence that this is winnable is that their flagship LÄS feature is broken in production while ours now cannot ship a citation that isn't in the text.*

**ORD typing removed → recall pause; one article per session; LÄS letter-references; plan-lock refresh (2026-07-24, part 2)** — the remaining four items from the founder's dogfooding notebook.
1. **Typed synonyms replaced by a graduated recall pause.** The typed-answer format was removed everywhere. Founder's case, which holds: HP never asks a candidate to *produce* a synonym, only to recognise one, so typing violated the transfer-appropriate-processing principle the corpus split was already built on. Worse, it was corrupting data — a **correct** answer missing from `accepted_synonyms` was scored wrong, and FSRS then rescheduled a known word as if it were unknown. (`flagged_synonyms` was, in effect, an admission we knew about the failure mode and were only measuring it.) What replaces it keeps the retrieval attempt but stops grading it: for words already answered correctly twice, the options are held back **3 s** behind a countdown ("Tänk på svaret först"), so the word has to be retrieved before it can be recognised. **New words get no pause** — pausing on a word the student cannot possibly know yet only costs time. `mcq_correct_streak` (migration 021) keeps its shape and changes job: it used to gate MCQ→typing, it now gates no-pause→pause. **The trap in this change** was FSRS latency: a naive implementation counts the 3 s pause as slow recall and rates every familiar word Hard, which is exactly the "Hard misuse" bug fixed in June wearing a new costume. The response timer therefore starts when the options *appear*, never at mount (`onReveal` → `markAnswerStart`), and the server's second, slower threshold set for typing was deleted rather than left to rot. Deleted: `OrdTyping`, `OrdFeedbackTyping`, `lib/utils/levenshtein`, `api/words/flag-synonym` (~330 lines, a closed island). **Honest note:** producing a word from memory *is* a stronger memory trace than choosing one, so this trades a real learning mechanism for a real data defect. The pause recovers part of it. No measurement will tell us if that was the right trade.
2. **LÄS options no longer shuffled, and three bugs fell out of it.** (a) **Eight explanations** across four articles named the answer by letter ("alltså svar D") while options were shuffled at render, so the letter was wrong on screen — all eight rewritten to describe *what makes the answer right*, which is better teaching anyway. (b) **Distractor hints were effectively random**: `LasFeedback` looked up `distractor_types[chosenLabel]` using the *displayed* label, which shuffling had already decoupled from the stored letter, so a wrong answer got an arbitrary explanation of its own wrongness. Fixed for free by removing the shuffle. (c) Removing the shuffle then *exposed* a position tell in article 007 (3 of 4 answers on A), fixed by swapping two options — carrying `distractor_types` across with them, since it is keyed by letter. Shuffling was safe to drop because ORD, not LÄS, is the format that needs it (ORD options come from fixed CSV columns with the correct synonym always first — **that shuffle must stay**), articles are never re-served to the same user, and the corpus-wide answer spread is even. Two new hard guards in `add-las-article.cjs`: letter references in explanations, and every answer in an article on one letter.
3. **One article per session, was 1 kort + 2 lång.** ~2100 words and 10 questions on top of the full ORD block put LÄS alone past 20 minutes. Format is picked **first**, weighted by how many unseen articles each pool still holds, then the best-scoring article in that pool wins. Picking the top-scoring article across both pools instead would have quietly starved the kort pool — weak-type score counts matching questions and lång articles have 4 to kort's 2, so lång would win nearly every time and the short format would never be practised.
4. **Plan/dashboard stayed padlocked until a manual reload.** `getOnboardingState` reads the DB correctly; the problem was *when*. The `(app)` layout is a server component, and client-side navigation reuses its cached RSC payload — the one rendered back when the diagnostic was still incomplete. `router.refresh()` now runs in `.finally` on the diagnostic-complete POST (the call that writes `completed_at`). One refresh covers all three gated surfaces, since it invalidates the whole router cache.

Also restored an `await` on `/api/session/complete` in the "avsluta för idag" path — it had been dropped in an uncommitted edit, against a warning written 40 lines above it in the same file. Without it a fast bounce into Studera can hit `/api/session/build` on a still-open row and slip a second daily session past the gate (double FSRS quota).

Files: `src/components/ord/OrdQuestion.tsx`, `src/components/ord/OrdFeedback.tsx`, `src/lib/fsrs/engine.ts`, `src/app/api/fsrs/review/route.ts`, `src/app/(app)/session/page.tsx`, `src/app/(app)/{test,diagnostic}/page.tsx`, `src/app/(app)/diagnostic/results/page.tsx`, `src/lib/session/{builder,planner}.ts`, `scripts/add-las-article.cjs`, `las/005–009*.json`; deleted `OrdTyping`, `OrdFeedbackTyping`, `levenshtein`, `api/words/flag-synonym`. Typecheck + production build green. **Not verified end-to-end** — the plan-lock fix in particular needs a real walk through the diagnostic. *North Star: goal #1 — but the honest headline is that this session fixed things rather than adding any, and the article bank went 13 → 13. At one article per session and 86 days to 18 oktober, the bank is now the binding constraint on the whole plan: ~85 articles needed, 13 exist, and when it empties LÄS silently vanishes from the session with no message. Content, not features, is the next real work.*

This is the *second* silent seed-mapping bug of this kind (`featured_ord_words` was never copied at all, found 2026-06-16) — a post-seed assertion comparing `las/*.json` against what actually landed in Postgres would have caught both, and is worth building before the corpus grows further.
2. **"FSRS" was leaking into the UI in 9 places** — dashboard, onboarding, plan (×3), session-complete (×2), locked dashboard, and the privacy policy. Replaced with what the algorithm *does for the user* ("Vi väljer ut orden du är på väg att glömma"), matching the voice already used on the plan page. The privacy-policy instance was also a small compliance smell: a GDPR notice has to describe collected data in language the reader understands, so "FSRS-data" became "din repetitionshistorik". Code comments keep the real name.
3. **Two ORD content fixes, one of which generalized.** `hektar` had an English word stranded in its example sentence ("Gården **encompassed** trettio hektar") — a sweep of all 877 example sentences found it was isolated. `naturtroget` had the vaguer problem the founder flagged ("mycket likt"), but the real defect was structural: the correct answer was the **only multi-word option** among four single-word distractors, so it was guessable without knowing the word. Changed to `realistiskt` (single word, same -t adjective form, already a vetted accepted synonym); "mycket likt" moved to `accepted_synonyms`. A corpus-wide scan found **1 clearly comparable case left (`kommission`)** and ~21 milder ones — logged as a to-build row because the rule ("options match in form" vs "correct answer is never the odd one out") is a founder decision, and some are unavoidable (`katharsis`, `fontanell` have no single-word synonym).
4. **Em-dash ban, now Non-Negotiable Rule #9.** Removed 106 em-dashes from user-visible text (96 Swedish UI strings across 34 files, 4 internal error codes changed on both the API and matching side, 6 in the ORD notes column). Every replacement hand-authored — comma, period, colon or parentheses depending on what the sentence does; a mechanical swap produces broken Swedish. **173 in code comments left alone** (stripped at build time, never user-visible) and the rule says so explicitly so no future session wastes effort there. Two clarifications written into the rule: the em-dash (—) is an English mark with no place in Swedish, but the Swedish **tankstreck (–) is legitimate typography and is not banned** — and **LÄS article bodies are exempt**, because they imitate the real Swedish journalism HP draws its texts from, where tankstreck is normal (36 instances there, ~1 per 350 words, within normal range). The ban is fully in force on LÄS explanations, which are Fattat's own voice.

Typecheck + production build verified green. *North Star: goal #1 — three of these are trust cracks rather than missing features, which is most of what separates "best app" from "competent app": a vocabulary aid that silently did nothing, developer jargon in a student's results screen, and a question answerable by spotting the odd-looking option. The `naturtroget` find matters beyond one row — it means our ORD items can leak the answer through form, which directly undermines the claim that Fattat measures real ability.*

## Closed items (removed from the "What's Still to Build" table)

**Post-seed assertion — closed 2026-07-24, built.** `scripts/verify-las-seed.ts`
(`npm run las:verify`) compares every `las/*.json` against the row it produced in Postgres:
scalar fields, body verbatim, question count and per-question `correct` / options keys /
`explanation` / `passage_anchor` / `distractor_types` keys, vocab-highlight words with
**non-empty** definitions and `index != -1`, and `featured_ord_words`. It also reports orphan
rows in the DB with no matching file, which is what a renamed title leaves behind. Written
because two silent seed-mapping bugs had shipped undetected (`featured_ord_words` never copied,
2026-06-16; `definition_sv` vs `definition` hiding ~110 definitions, 2026-07-24). Both would
have been caught by it. First run confirmed four vocab highlights sitting at index -1 in
production.

**ORD format-tell audit — closed 2026-07-24, decided and applied.** The open question was
whether the rule should be *"options must match in form"* or *"the correct answer must never be
the odd one out"*. Settled by measuring the 537 real past-HP items in `ord-database.csv`: the
correct answer is multi-word in **31.1%** of real items, is the *only* multi-word option in
**1.1%**, and the only single-word option in **0.0%** (zero of 537). Form-matching is therefore
not what HP does; uniqueness of form is the tell. Rule adopted: **at least one distractor must
share the correct answer's word-count class.** This keeps `katharsis` / `fontanell` / `unikum`
writable (no single-word synonym exists) and shrank the feared ~22-row pass to **8 curated
rows**, all from one drifted batch (id 830–847, kultur), fixed by swapping one distractor each.
Past-HP rows are exempt and were not touched: they reproduce real exams verbatim, and "fixing"
them would falsify the source. Enforced by `scripts/lint-ord-corpus.cjs` (`npm run ord:lint`),
which on its first run also caught `klausul` listing `paragraf` as both a distractor and an
accepted synonym, making that item unanswerable.

**`flagged_synonyms` review — closed 2026-07-24, obsolete.** Both `flagged_synonyms` and the
`accepted_synonyms` column existed only to judge *typed* answers, and typing is gone. The table
(2 rows, both correct answers wrongly graded, which is the exact failure mode that justified
killing typing), the column, and the existing rows are all left in place (harmless, cheap to
undo), but nothing reads them. The ORD content skills no longer generate `accepted_synonyms`.
Verified live via Supabase MCP at the time: migration 024 applied, 13 articles in DB matching
disk, vocab definitions present (the bug was display-only, since fixed), 4 waitlist signups.

**Founder creates account live on Day 0 video — superseded 2026-06-11.** The public dogfooding
series was paused; the founder trains privately for HP 2026-10-18 instead. The still-live parts
of that row (HP-anmälan deadline, private footage, content growth) moved to a "Founder must-dos"
row in `CLAUDE.md`.

**ORD morphology decode in feedback — v1 (2026-06-16)** — gives students a tool for the unknown-word problem the övningsprov explainer only *names* ("du möter alltid okända ord"). After a full morphological sweep of all 877 ORD words (`analysis/ORD_morfologi.md`), the key finding was that the bigger lever isn't the headword but the **answer options** — 3 753 distinct option words vs 877 headwords, and "not knowing what the alternatives mean" is the real bottleneck (founder + friends). `decodeWord()` (`src/lib/ord/morphology.ts`) breaks a Swedish word into its building blocks, **computed at runtime** (not a stored field — most option words aren't DB headwords) and **conservative** (returns `null` unless confident; silence beats a wrong split). v1 covers meaning-bearing suffixes only — `-lös`/`-full`/`-fri`/`-bar`/`-värd`/`-värt`/`-aktig` — verified against the full corpus at 60 confident decodes, 0 wrong splits. Guards: leading-`o` words skipped (an unhandled negation would invert meaning — `oanvändbar`); a false-positive set (`underbar`, `uppenbar`, `överfull`, `varaktig`…); paraphrase only from an unambiguous base so a stem like `gräns` is never corrupted to `grän`. Surfaced as a "Byggstenar" block in ORD feedback **post-answer only** (Rule #2 — never a hint): correct answer → headword + correct synonym (snappy); wrong answer → headword + every option. Dropped from v1: `-sam` (too semantically varied for one honest gloss). Next on the same rails: prefixes (negation first), then compound-splitting, then a curated English-cognate table. Files: `src/lib/ord/morphology.ts` (new), `src/components/ord/MorphemeBreakdown.tsx` (new), `src/components/ord/OrdFeedback.tsx`, `src/components/ord/OrdFeedbackTyping.tsx`. Production build verified green. *North Star: goal #1 — a transferable skill that lifts performance on words the student never studied, which no Swedish HP competitor teaches; pedagogy, not access (the locked vision).*

## Appendix — why the commit & deploy rules exist

> The rules themselves live in `CLAUDE.md`. This is the reasoning behind each one, kept
> here because it only needs reading once. Agreed with the founder 2026-07-24.

Agreed with the founder 2026-07-24, after a session where 9 fixes were held uncommitted, one repo-wide sweep entangled 34 files, and a first attempt bundled four unrelated changes into a single commit. Each rule below exists because something specific went wrong.

**1. Commit each finished unit of work — proactively, without asking.**
A "unit" is one thing describable in a sentence and revertable alone. Do not ask "should I commit this?"; the founder is non-technical, rarely commits unprompted, and once let ~150 files pile up for months. Asking moves the decision to the wrong person and produces backlogs.

**2. Never commit code that doesn't compile.**
Typecheck and `npm run build` green *before* committing. This is what makes each commit a safe return point rather than just a timestamp, and it's what lets the founder revert any single commit without breaking the app.

**3. Repo-wide sweeps get their own commit, ordered first or last — never interleaved.**
The 2026-07-24 em-dash sweep touched 34 files in the middle of feature work and forced two unrelated concerns to share a commit. Mechanical passes (copy sweeps, renames, formatting) must not be interleaved with behavioural changes.

**4. Never push without the founder's explicit OK.**
Unchanged and most important: push to `main` auto-deploys production at fattat.se via Vercel. Pushing is publishing, not a technical step. Commits stack locally until the founder says go.

**5. Fixed pre-push checklist, walked and reported every time:**
   - production build green
   - every migration the code depends on is applied to the production Supabase (the live site can otherwise run code months ahead of the prod schema)
   - a plain-Swedish summary of what changes **for the user**, not what changed in the code

**6. Deploy in deliberate batches, not per commit.**
With the founder as sole user there is no value in nine pushes a day, only nine chances to ship something half-finished. Accumulate, then deploy a coherent batch.

**Still true:** solo workflow, commit straight to `main`, no branches (branching adds overhead with no reviewer). Commit messages explain *why*, not just what — the founder reads them to understand their own project.
